# 영상 플랫폼 설계 문서

작성일: 2026-06-23
대상 경로: `C:\dev\플랫폼\영상`

## 목적

유튜브형 영상 플랫폼을 클론 코딩 방식으로 구현하되, 초기에는 실제 운영 서비스 전체가 아니라 화면과 사용자 흐름이 완성된 프론트엔드 MVP를 만든다. 사용자는 홈에서 영상을 발견하고, 검색하고, 상세 페이지에서 시청하고, 채널을 확인하고, 업로드 흐름을 경험할 수 있어야 한다.

## 권장 접근

추천 접근은 프론트엔드 MVP 우선 방식이다.

대안은 세 가지다.

1. 프론트엔드 MVP 우선
   - 장점: 가장 빨리 브라우저에서 결과를 확인할 수 있다.
   - 단점: 초기 데이터는 목업이므로 실제 서비스 기능은 제한된다.
   - 판단: 현재 프로젝트 상태와 가장 잘 맞는다.

2. 풀스택 우선
   - 장점: 로그인, DB, 업로드까지 실제 구조를 빨리 잡을 수 있다.
   - 단점: 초기 범위가 커지고 화면 완성도가 늦어진다.
   - 판단: MVP 이후 2차 목표로 적합하다.

3. 디자인 시스템 우선
   - 장점: 장기적으로 UI 일관성이 좋다.
   - 단점: 실제 사용자 흐름 완성이 늦어진다.
   - 판단: 화면이 어느 정도 자리 잡은 뒤 분리하는 편이 낫다.

## 기술 선택

- React: 화면 컴포넌트 구현
- TypeScript: 데이터 타입 안정성 확보
- Vite: 빠른 개발 서버와 빌드
- React Router: 페이지 라우팅
- lucide-react: 인터페이스 아이콘
- CSS: 초기 전역 스타일 기반, 필요 시 모듈화

후속 확장 후보:

- Node.js + Express 또는 NestJS
- PostgreSQL
- S3 호환 오브젝트 스토리지
- React Query
- 인증 시스템

## 화면 구조

### 홈

추천 영상 목록, 카테고리 칩, 상단 검색창, 업로드 버튼, 사이드바를 제공한다.

### 검색 결과

검색어를 기준으로 영상 목록을 필터링하고, 결과 없음 상태를 제공한다.

### 영상 상세

플레이어 영역, 영상 메타데이터, 채널 정보, 액션 버튼, 설명, 댓글, 추천 영상 목록을 제공한다.

### 채널

채널 배너, 프로필, 채널 설명, 구독자 수, 해당 채널 영상 목록을 제공한다.

### 업로드

제목, 설명, 카테고리, 썸네일 정보를 입력하고 등록 흐름을 시뮬레이션한다.

## 단계별 계획

### 1단계: 기반 점검

현재 프로젝트 구조와 빌드를 확인하고 문서와 브라우저용 계획 화면을 준비한다.

### 2단계: 홈 화면 개선

영상 카드, 그리드, 카테고리, 반응형 레이아웃을 실제 플랫폼처럼 다듬는다.

### 3단계: 영상 상세 화면 개선

플레이어, 댓글, 추천 영상, 채널 정보의 정보 구조와 시각 완성도를 높인다.

### 4단계: 검색과 채널 흐름 개선

검색 결과와 채널 페이지를 자연스럽게 연결한다.

### 5단계: 업로드 흐름 MVP

폼 검증, 등록 시뮬레이션, 성공 상태를 구현한다.

### 6단계: 품질 정리

모바일 대응, 접근성, 빈 상태, 오류 상태, 빌드 검증을 마친다.

### 7단계: 백엔드 확장 준비

데이터 접근 계층과 API 명세를 분리해 실제 서버 전환을 준비한다.

## 오류 처리

- 존재하지 않는 영상 ID는 "영상을 찾을 수 없음" 상태로 처리한다.
- 검색 결과가 없으면 빈 상태 메시지와 홈 이동 선택지를 제공한다.
- 업로드 필수 입력값이 비어 있으면 필드별 오류 메시지를 제공한다.
- 이미지 URL이 깨질 경우 기본 썸네일 또는 색상 블록 대체 UI를 제공한다.

## 테스트 계획

- `npm run build`로 TypeScript와 Vite 빌드를 확인한다.
- 브라우저에서 홈, 검색, 영상 상세, 채널, 업로드 라우트를 수동 확인한다.
- 모바일 폭에서 헤더, 사이드바, 영상 카드, 상세 페이지가 겹치지 않는지 확인한다.
- 업로드 폼의 필수값 검증을 확인한다.

## 승인 기준

이 설계가 승인되면 구현 계획을 세부 작업 목록으로 나누고, 1단계부터 순서대로 진행한다. 구현 중에는 각 단계가 끝날 때마다 빌드와 브라우저 확인을 수행한다.
