# 영상 플랫폼 프로젝트 기획서 / 계획서

작성일: 2026-06-23

## 1. 프로젝트 개요

`영상` 프로젝트는 유튜브와 비슷한 사용 흐름을 가진 영상 플랫폼 웹 애플리케이션이다. 처음부터 실제 대용량 영상 업로드, 인코딩, 추천 알고리즘, 광고, 결제까지 구현하지 않고, 사용자가 영상을 탐색하고 시청하고 검색하고 채널을 확인하며 업로드 흐름을 경험할 수 있는 프론트엔드 MVP를 먼저 완성한다.

현재 폴더에는 이미 Vite, React, TypeScript 기반 프로젝트가 준비되어 있으므로 이 기반을 유지한다. 초기 목표는 "실제 서비스처럼 보이고 움직이는 화면"을 만드는 것이다. 이후 API 서버, 데이터베이스, 인증, 실제 파일 업로드로 확장할 수 있도록 데이터 타입과 화면 구조를 분리한다.

## 2. 최종 목표

최종 목표는 사용자가 영상 콘텐츠를 발견하고, 검색하고, 시청하고, 채널과 업로드 흐름을 자연스럽게 경험할 수 있는 유튜브형 영상 플랫폼을 만드는 것이다.

완성 기준:

- 홈 화면에서 추천 영상 목록과 카테고리 필터를 볼 수 있다.
- 영상 상세 화면에서 플레이어, 제목, 설명, 조회수, 채널 정보, 댓글, 추천 영상을 볼 수 있다.
- 검색어를 입력하면 검색 결과 화면으로 이동하고 관련 영상 목록을 보여준다.
- 채널 페이지에서 채널 정보와 해당 채널의 영상 목록을 볼 수 있다.
- 업로드 페이지에서 영상 메타데이터를 입력하고 새 영상을 등록하는 흐름을 경험할 수 있다.
- 데스크톱과 모바일에서 주요 화면이 깨지지 않고 사용할 수 있다.
- 이후 백엔드 API, DB, 인증, 파일 저장소로 확장하기 쉬운 구조를 가진다.

## 3. 초기 MVP 범위

초기 버전은 프론트엔드 중심 MVP로 진행한다.

포함 범위:

- 홈, 검색 결과, 영상 상세, 채널, 업로드 화면
- 목업 영상/채널/댓글 데이터
- 라우팅과 화면 전환
- 반응형 레이아웃
- 업로드 폼 검증과 등록 흐름 시뮬레이션
- 빈 상태, 오류 상태, 로딩 상태의 기본 UI

제외 범위:

- 실제 영상 파일 업로드와 인코딩
- 로그인, 회원가입, 권한 관리
- 실시간 추천 알고리즘
- 광고, 결제, 멤버십
- 관리자 페이지
- 대댓글, 알림, 라이브 스트리밍

## 4. 사용할 기술

### 프론트엔드

- React: 화면을 컴포넌트 단위로 나누고 재사용하기 위해 사용한다.
- TypeScript: 영상, 채널, 댓글 같은 데이터 구조를 명확히 정의한다.
- Vite: 빠른 개발 서버와 빌드 환경을 제공한다.
- React Router: 홈, 검색, 시청, 채널, 업로드 페이지 라우팅을 담당한다.
- CSS: 초기에는 전역 CSS와 명확한 클래스 구조를 사용한다. 필요하면 이후 CSS Modules나 디자인 시스템으로 분리한다.
- lucide-react: 검색, 업로드, 메뉴, 좋아요 같은 인터페이스 아이콘에 사용한다.

### 데이터와 상태

- 초기에는 `src/data`의 목업 데이터를 사용한다.
- `src/types`에 영상, 채널, 댓글 타입을 정의한다.
- 업로드 흐름은 클라이언트 상태로 먼저 처리한다.
- 이후 API 연동 시 `src/services` 또는 `src/api` 레이어를 추가한다.

### 확장 후보

- Node.js + Express 또는 NestJS: 백엔드 API 서버
- PostgreSQL: 사용자, 영상, 채널, 댓글, 구독 데이터 저장
- S3 호환 오브젝트 스토리지: 영상 파일과 썸네일 저장
- React Query: 서버 상태 캐싱과 동기화
- 인증: 세션 또는 JWT 기반 로그인

## 5. 주요 화면

### 5.1 홈

- 상단 헤더: 로고, 검색창, 업로드 버튼, 사용자 메뉴
- 좌측 사이드바: 홈, 탐색, 구독, 보관함
- 카테고리 칩: 전체, 개발, 음악, 게임, 뉴스 등
- 영상 카드 그리드: 썸네일, 제목, 채널명, 조회수, 업로드 시점

### 5.2 검색 결과

- 검색어 표시
- 검색 결과 영상 목록
- 결과 없음 상태
- 영상 카드 클릭 시 상세 페이지 이동

### 5.3 영상 상세

- 영상 플레이어 영역
- 제목, 조회수, 업로드 날짜
- 좋아요, 공유, 저장 버튼
- 채널 정보와 구독 버튼
- 설명 영역
- 댓글 목록
- 추천 영상 목록

### 5.4 채널

- 채널 배너
- 프로필 이미지, 채널명, 구독자 수
- 채널 소개
- 채널 영상 목록

### 5.5 업로드

- 제목 입력
- 설명 입력
- 카테고리 선택
- 썸네일 URL 입력 또는 미리보기
- 폼 검증
- 등록 완료 후 생성된 영상 상세 페이지로 이동하는 흐름

## 6. 중간 목표

### 1단계: 프로젝트 기반 점검

- 현재 Vite + React + TypeScript 구조 확인
- 라우팅과 레이아웃 점검
- 빌드가 정상 동작하는지 확인
- 깨진 기획 문서를 정상 문서로 교체

완료 기준:

- `npm run build`가 성공한다.
- 주요 라우트가 브라우저에서 열린다.
- 계획서와 브라우저용 기획 화면이 준비된다.

### 2단계: 홈 화면 완성도 개선

- 영상 카드 그리드 정리
- 카테고리 필터 또는 칩 UI 개선
- 카드 호버, 썸네일 비율, 메타데이터 표시 정리
- 모바일 레이아웃 점검

완료 기준:

- 홈 화면이 실제 영상 플랫폼처럼 보인다.
- 영상 카드를 클릭하면 상세 페이지로 이동한다.

### 3단계: 영상 상세 화면 강화

- 플레이어 영역 시각 완성도 개선
- 추천 영상 사이드바 정리
- 댓글 목록과 채널 정보 UI 개선
- 빈 상태와 없는 영상 상태 처리

완료 기준:

- 영상 상세 페이지가 시청 화면으로 자연스럽게 느껴진다.
- 잘못된 영상 ID 접근 시 사용자에게 이해 가능한 상태를 보여준다.

### 4단계: 검색과 채널 흐름 완성

- 검색창 입력과 결과 페이지 이동 개선
- 검색어 기반 필터링 정리
- 채널 페이지 레이아웃 개선
- 채널별 영상 목록 연결

완료 기준:

- 검색어 입력부터 결과 확인까지 흐름이 끊기지 않는다.
- 채널명 또는 채널 요소 클릭 시 채널 페이지로 이동한다.

### 5단계: 업로드 흐름 MVP

- 업로드 폼 검증
- 입력값 기반 영상 등록 시뮬레이션
- 성공 상태와 이동 흐름 구현
- 향후 API 연동을 고려한 데이터 생성 함수 분리

완료 기준:

- 사용자가 새 영상 정보를 입력하고 등록 흐름을 경험할 수 있다.
- 필수값 누락 시 명확한 안내가 나온다.

### 6단계: 품질 정리

- 반응형 레이아웃 보정
- 접근성 기본값 점검
- 중복 스타일 정리
- 주요 사용자 흐름 수동 테스트
- 빌드 검증

완료 기준:

- 데스크톱과 모바일에서 주요 화면이 깨지지 않는다.
- 빌드와 주요 라우트 검증이 완료된다.

### 7단계: 백엔드 확장 준비

- 데이터 접근 로직을 서비스 레이어로 분리
- API 명세 초안 작성
- DB 엔티티 초안 작성
- 실제 파일 업로드와 인증을 위한 후속 계획 수립

완료 기준:

- 목업 데이터에서 실제 API로 전환하기 쉬운 구조가 된다.

## 7. 권장 진행 방식

이 프로젝트는 "프론트엔드 MVP 먼저, 백엔드 확장 나중" 방식으로 진행한다.

이유:

- 현재 프로젝트가 이미 React/Vite 기반으로 만들어져 있다.
- 사용자가 가장 빨리 확인할 수 있는 결과물은 브라우저 화면이다.
- 영상 플랫폼은 기능 범위가 크므로 처음부터 풀스택으로 가면 범위가 쉽게 커진다.
- 화면, 데이터 타입, 사용자 흐름을 먼저 안정화하면 이후 백엔드 설계가 쉬워진다.
